# Astro Suite 0.2.0 Release Candidate 1

`v0.2.0-rc.1` checkpoints the first integrated uncertainty and mission-assurance product increment
after `v0.1.0`.

## Highlights

- Suite-owned ballistic, lifting, and guided reentry simulation, optimization, and trajectory
  handoff products.
- A launch-to-reentry mission lifecycle with explicit state, epoch, mass, phase, artifact, and
  requirement continuity.
- General uncertainty campaigns using deterministic pseudorandom, Latin hypercube, Sobol, sweep,
  and model-ensemble sampling with resumable artifacts, explicit failure outcomes, bounded process
  execution, statistics, stopping, sensitivity, and margin attribution.
- Integrated digital-twin campaign inputs and metrics for power, thermal, ADCS, communication,
  coverage, mass, and design margins, including full-orbit eclipse and energy accounting.
- Post-launch mission assurance connecting insertion, synthetic tracking, orbit determination,
  bounded correction design, estimate/truth replay, and the corrected digital twin.
- Paired matched/model-mismatch assurance validation with causal tracking, unpooled outcomes,
  digest verification, and a typed calibration-evidence manifest covering all configured numeric
  dimensions.
- Typed AI campaign plans and integrity-checked surrogate artifact contracts. Learned surrogate
  training remains stopped because the checked local evaluators do not meet the minimum cost gate.

## Evidence Boundary

This candidate publishes deterministic simulation and configured design-space evidence. It does not
claim RF acquisition, operational navigation, flight-command authority, mission-success
probability, production covariance certification, standards-grade calibration, flight-qualified
GNC, thermal or EPS certification, or operational constellation coverage.

The paired assurance calibration status remains `illustrative`. External references inform some
parameter envelopes, but mission-specific station residuals, launcher covariance, propulsion
execution residuals, and subsystem test evidence are still required for calibrated mission claims.

## Compatibility

- Python: 3.12 or newer.
- Package version: `0.2.0rc1`.
- Campaign runtime contract: `1.2`.
- Existing suite-owned v1 product and artifact schemas remain explicit in their serialized outputs.
- Optional Orekit, RocketPy, Dymos/OpenMDAO, TudatPy, and JAX paths remain runtime-gated adapters or
  research surfaces; they are not required for the local release gate.

## Candidate Gate

Before tagging, the reviewed candidate commit must pass:

```bash
python -m ruff check .
python -m mypy
python -m pytest -q
python -m build
git diff --check
```

The built wheel must report `Version: 0.2.0rc1`, contain every declared suite package, and execute
the public mission-assurance validation and verification workflow from outside the repository.
