# Astro Suite 0.2.0 Release Candidate 2

`v0.2.0-rc.2` consolidates the 28 commits merged after `v0.2.0-rc.1` into a second
candidate for the `v0.2.0` release line.

## Highlights

- Deterministic, typed review products for paired mission-assurance evidence, cross-run review
  comparison, and launch-to-reentry lifecycle evidence.
- Mission calibration evidence contracts for station residuals, propulsion execution residuals,
  and insertion covariance, with fail-closed derivation and promotion rules.
- A four-cell truth/estimator model-form matrix that preserves profiles and contrasts without
  pooling them into a model-success probability.
- Suite-owned production covariance acceptance criteria that keep numerical agreement,
  implementation independence, force coverage, empirical consistency, and sample sufficiency as
  separate gates.
- Native Orekit/Tudat covariance comparison evidence and a 512-realization empirical Tudat
  truth-error campaign. The checked result passes 11/11 epochs, reports mean NEES
  `6.152680885241317`, and observes 480/512 samples inside the individual bound with an exact
  one-sided 95% binomial lower bound of `0.9169573165477053`.
- Explicit units on every digital-twin design margin and v2 workflow identifiers for integrated
  and constellation digital-twin artifacts.

## Evidence Boundary

This candidate publishes deterministic simulation, comparison, and configured design-space
evidence. The native covariance campaign is machine-scoped validation evidence. It is not flight,
navigation, production, operational, or certification authority.

Mission-assurance calibration remains `illustrative` unless reviewed mission-specific evidence
supports every promoted bound. Model-form results remain separate, unpooled comparisons. Typed AI
plans compile allow-listed review steps; deterministic verification gates retain decision and
execution authority.

## Compatibility

- Python: 3.12 or newer.
- Package version: `0.2.0rc2`.
- Campaign runtime contract: `1.2`.
- Campaign resume compatibility advances with the package identity from `0.2.0rc1` to
  `0.2.0rc2`; artifact schema and campaign-runtime versions remain independent contracts.
- Integrated and constellation digital-twin results now emit `integrated_digital_twin_v2` and
  `constellation_digital_twin_v2`. Their `DesignMargin` products require a non-empty `unit`; this
  is an intentional artifact-contract change from RC.1. RC.1 twin artifacts without structured
  units are unsupported by the v2 loader and must be regenerated; Astro Suite does not infer units
  from margin names or values.
- New assurance review, lifecycle review, model-form matrix, mission calibration inspection, and
  covariance validation commands are additive public surfaces.
- Optional Orekit, RocketPy, Dymos/OpenMDAO, TudatPy, and JAX paths remain runtime-gated adapters or
  research surfaces; they are not required for the local release gate.

## Candidate Gate

Before tagging, the reviewed candidate commit must pass:

```bash
python -m ruff check .
python -m mypy
python -m pytest -q
python -m build
git diff --check
```

The built wheel must report `Version: 0.2.0rc2`, contain every declared suite package, and execute
representative public lifecycle-review and covariance-validation workflows from outside the
repository. GitHub CI, merged-commit verification, and the annotated tag must all resolve to the
same reviewed commit.
