# Astro Suite 0.2.0

`v0.2.0` promotes the reviewed Astro Suite 0.2 release-candidate line to a final package identity.
The final-release delta from `v0.2.0-rc.2` is limited to package and campaign compatibility
identity, final release notes, tests, and durable release state. Physics, public APIs, artifact
schemas, checked evidence, and claim boundaries are unchanged.

## Highlights

- Suite-owned reentry, launch-to-reentry lifecycle, uncertainty, digital-twin, and post-launch
  mission-assurance products.
- Deterministic assurance and lifecycle review, cross-run comparison, typed mission calibration
  evidence, and a four-cell model-form validation matrix.
- Production covariance acceptance criteria plus native Orekit/Tudat comparison and a
  512-realization empirical truth-error campaign.
- Typed, allow-listed AI planning and review boundaries with deterministic promotion and execution
  authority.
- Explicit units on digital-twin design margins and v2 integrated/constellation twin artifact
  identifiers.

## Evidence Boundary

This release publishes deterministic simulation, comparison, review, and configured design-space
evidence. The checked covariance campaign is machine-scoped validation evidence. Nothing in this
release claims flight qualification, operational navigation, production certification, regulatory
authority, calibrated mission-success probability, or autonomous command authority.

Mission-assurance calibration remains `illustrative` unless reviewed mission-specific evidence
supports every promoted bound. Model-form results remain separate and unpooled.

## Compatibility

- Python: 3.12 or newer.
- Package version: `0.2.0`.
- Campaign runtime contract: `1.2`.
- Campaign resume compatibility advances from package identity `0.2.0rc2` to `0.2.0`; artifact
  schema and campaign-runtime versions remain independent contracts.
- RC.1 digital-twin artifacts without structured margin units remain unsupported by v2 loaders and
  must be regenerated. Astro Suite does not infer engineering units from names or values.
- Optional Orekit, RocketPy, Dymos/OpenMDAO, TudatPy, and JAX paths remain runtime-gated adapters or
  research surfaces and are not required for the local release gate.

## Final Gate

Before tagging, the reviewed final-release commit must pass:

```bash
python -m ruff check .
python -m mypy
python -m pytest -q
python -m build
git diff --check
```

The built wheel must report `Version: 0.2.0`, contain every declared suite package, and reproduce
the representative public lifecycle-review and covariance-validation workflows from outside the
repository. GitHub CI, the merged commit, detached verification, and the annotated `v0.2.0` tag
must resolve to the same reviewed release content.
