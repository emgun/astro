# Validation Matrix

Date: 2026-07-17

This matrix lists the current validation surfaces for Astro Suite. The suite treats local
deterministic workflows and unit-level backend contracts as required regression references.
Optional runtime commands are smoke-gated adapter checks and are not required local release gates
unless the matching runtime is intentionally installed for a live validation campaign.

## Required Local Gates

These gates must run without optional Orekit, TudatPy, RocketPy, Dymos/OpenMDAO, or JAX runtimes.
Rows that exercise optional engines through live CLI commands belong in `Optional Backend Gates`.

## Backend Boundary Rule

No optional backend may return native engine objects through public products. All backends must map
into suite-owned `Trajectory`, `EstimateResult`, `LaunchTrajectory`, `LaunchPitchTuningResult`,
`ReentryResult`, `MissionLifecycleResult`, `MissionAssuranceCase`, or `MonteCarloResult` models and include backend
provenance in product metadata when available.
